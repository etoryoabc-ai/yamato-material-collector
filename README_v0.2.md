# 大和噺｜歴史資料収集アプリ v0.2

YouTube制作向けの歴史資料調査・整理ツールです。字幕生成ツールから独立したPythonプロジェクトです。Windowsの操作画面から使えます。原稿や画像はGitHubへ送信しません。検索語とUser-Agentの連絡先はCommonsに送信します。

## Windowsで使う（コマンド入力不要）

1. Python公式サイト https://www.python.org/downloads/windows/ からPython 3.10以降をインストールします。`Add python.exe to PATH` と Tcl/Tk（通常は標準選択）を有効にしてください。Python本体は同梱していません。
2. 配布ZIPを右クリックして「すべて展開」。ZIP内から直接実行せず、書き込み可能なフォルダに置きます。
3. `input` フォルダに、UTF-8形式で **完成原稿.txt** を保存します。Windowsの拡張子表示を有効にし、`.txt.txt` になっていないことを確認してください。
4. **起動.bat** をダブルクリックします。初回は画面上のリンクからCommonsの再利用条件・API利用条件・User-Agent条件を読み、確認欄にチェックし、自分の連絡先URLまたはメールを入力します。
5. 「検索を開始」を押します。次回から設定済み・原稿ありならbat起動時に自動検索し、過去に個別確認を登録済みの画像は自動取得します。未確認の画像は候補記録に留めます。
6. 検索後「個別確認・見送りを登録」を開きます。候補の出典を開き、商用利用条件、必要クレジット、描写年代・内容、原資料か復元図かを確認して保存します。見送りも理由付きで保存できます。
7. 「確認済み画像を取得」を押すと、再検索して条件を満たす画像だけ保存します。候補が前回の検索結果から消えた場合は取得されません。
8. 「結果フォルダを開く」から `画像プレビュー.html`、CSV、レポートを確認します。画像フォルダはResolveのメディアプールへ読み込めます。

チェックは利用者が実際に確認した記録です。ソフトが現行規約を自動検証するわけではありません。個別確認なしで「取得成功」にしません。クレジット記載が不要なら、その根拠と「表示義務なし」を記録してください。動画への採用は史実・権利の根拠を確認して判断してください。

## ネットワークを使えるWindowsでの実行

通常のHTTPS接続で次の公式ホストにアクセスできる必要があります。

- `commons.wikimedia.org`：検索API・資料ページ
- `upload.wikimedia.org`：画像原本
- `www.mediawiki.org`、`foundation.wikimedia.org`：API・User-Agent条件
- ライセンス確認先（`creativecommons.org` 等）と出典機関の公式サイト

組織のプロキシ・ファイアウォールを使用する場合は管理者が許可した設定で利用してください。TLS検証は有効のままです。403・429等のエラーや接続失敗はログに残し、制限を迂回しません。既定でリクエスト間隔1秒、タイムアウト20秒、画像上限80MBです。大量検索せず、初めは短い原稿で試してください。

国内のNDL・国立公文書館・東京都立図書館は入口の接続確認と手動検索計画までです。これらの自動画像取得は未実装です。

## Commonsの実画像取得テスト

**Commons取得テスト.bat** をダブルクリックします。実際のCommons APIへ江戸の町並みなどの検索語を送り、候補の現行メタデータ・出典URLを保存します。固定の資料名や利用許諾は捏造しません。

1. 初回設定を行い「検索を開始」。候補が見つかるか確認します。
2. 「個別確認・見送りを登録」で歴史資料の描写・年代・権利を出典ページで確認します。
3. 「確認済み画像を取得」で原画像を取得します。
4. 結果画面の取得件数、`取得済み.csv`、実ファイル、プレビューを確認します。取得0件は取得成功ではありません。

検索の接続成功と実画像の保存成功は別々です。利用条件不明ならダウンロードせず記録します。サンプル原稿はテストであることを明示しています。

## 記録区分

| ファイル | 内容 |
|---|---|
| 素材一覧.csv | 発見候補すべて、確認状況・記録区分・判定理由 |
| 取得済み.csv | 実際に保存成功した画像 |
| 取得見送り.csv | 明示的な見送り、許可対象外ライセンス、重複、確認済みだが検索のみの実行 |
| 利用条件未確認.csv | 個別の権利・史実確認が不足する候補 |
| 取得エラー.csv | 確認済み画像を取得しようとして失敗した記録 |
| 実行結果.json | 候補数・取得数・区分別件数・エラー |

区分ごとのCSVは候補0件でもヘッダーを作成します。利用条件未確認には史実確認不足も含み、判定理由に記録します。APIが返さない情報は「不明」です。明示的な見送り設定は取得許可より優先されます。

毎回 `results/素材収集_日時/`（テストは `Commons検証_日時`）に独立した結果を作成し、以前の結果を上書きしません。`logs` に実行ログ、各結果の `証跡` にAPI応答・確認記録を保存します。画像はJPEG/PNG原本のみ、SHA256完全一致の重複除外。CC BY-SAや非商用ライセンスはMVP対象外です。

## GitHubで独立管理する

推奨リポジトリ名は **yamato-material-collector**。字幕生成ツールのリポジトリとは別に、新規リポジトリを作成してください。ソース・README・テスト・batだけを管理し、個人情報や素材は `.gitignore` で除外しています。

GitHub Desktopでコマンド入力なしに保存できます。

1. GitHub Desktop https://desktop.github.com/ をインストールしてログイン。
2. `File → Add local repository` でこのフォルダを選択。ZIPに `.git` がなければ、案内に従いこのフォルダで `create a repository`（Gitの初期化）を行います。
3. Changesに表示された内容を確認し、`Commit to main`。
4. `Publish repository` で `yamato-material-collector` を指定。個人用ならPrivateを選びます。
5. 以後、更新をコミットして `Push origin`。

この配布物は既存字幕リポジトリを変更しません。GitHub上の新規リポジトリ作成・アップロードはまだ行っていません。原稿・画像・設定を公開しないよう、Publish前にChangesを確認してください。ソースの再配布ライセンスは未指定であり、取得画像のライセンスとは別です。

## 開発・検証と制約

開発者向け：`python -m unittest -v test_collector.py`。標準ライブラリのみです。GUIのデスクトップ操作とbatはWindowsでの実機確認が必要です。この環境はLinuxであり、Windows実機テストを実施したとは報告しません。

従来のCLIも `collector.py` で利用できます。旧説明は `README_v0.md`。GUIはUTF-8入稿を想定し、他の文字コードでは変換して保存してください。原稿解析はルール方式、全自動の史実・権利判断ではありません。検索スナップショットからの再開、IIIF/TIFF/PDF、近似画像重複、Resolveタイムライン生成は未対応です。

既存v0のフォルダとZIPは変更せず保存しました。今回のプロジェクトは新規フォルダです。クラウドのネットワーク制限によりライブ収集成功は未検証です。Windowsの実接続テストで確認してください。
