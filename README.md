# 大和噺｜原稿連動 映像素材アシスタント v0.5

完成原稿からシーン順の画像候補カタログを作り、画像を見ながら選んでResolve用フォルダへ整理するWindows向けアプリです。Python 3.10以降＋Tcl/Tk、標準ライブラリのみ。**無料ルール解析と、利用者が選ぶ任意の有料AI解析を区別**しています。

**[Windows用 v0.5 ZIP](https://github.com/etoryoabc-ai/yamato-material-collector/raw/refs/heads/main/downloads/yamato-material-collector-v0.5.zip)**


## v0.5で修正した停止原因

v0.4は、Webページ巡回のrobots判定を正式なAction APIリクエストにも同一にかけ、HTTP要求前に停止していました。v0.5は公開されたAction APIの利用規則に従う専用クライアントとして、**固定エンドポイントの読み取り専用JSON検索・画像情報取得だけ**を処理します。HTML巡回、編集API、任意の `/w/` URLへのアクセスは拒否します。画像配信先のrobots判定と、サーバーの実際の拒否・待機指示は引き続き適用します。サムネイルのrobots確認先が別用途ページへ転送される場合は、サムネイルだけを未取得にし、確認済みの画像配信先から保存した原本を縮小表示します。未確認サムネイルの代替ホスト取得はしません。APIが画像URLへ付与する `utm_source` 等の追跡パラメータを画像取得として扱い、HTML巡回と誤判定しないようにしました。詳細は `調査_APIとrobots.md` に比較と公式資料を記載しました。

**Windows CI実測（2026-11-01）**：API発見182件・関連候補25件・原本10枚保存・SHA256照合10枚・Edgeで画像10枚デコード・JavaScriptエラー0。API条件分類可19件／要確認6件（最終確認完了とは別）。単体テスト37件成功。v0.3方式の比較検索も10件成功しました。サムネイルのrobots確認不能10件は記録し、未取得のサムネイルを取得済みとせず、許可された原本の縮小表示で検証しています。

[Windows検証結果](https://github.com/etoryoabc-ai/yamato-material-collector/actions/runs/41272354314)／[実測JSON](検証/v05_Windows10枚取得検証.json)。クラウドは引き続きプロキシ403で原本0枚であり、環境ごとの結果を混同しません。

v0.3・v0.4のソースはGit履歴と旧ZIP、ローカルの旧フォルダに保持。v0.5は別フォルダへ展開してください。字幕ツールのリポジトリとは独立しています。

完成原稿はまだ提供されていないため、初回の検証には「100万人都市の江戸」のテスト用短文を使います。テスト原稿は史実検証済みの完成原稿ではありません。

## Windowsでの使い方：3ステップ

準備： https://www.python.org/downloads/windows/ からPython 3.10以降をインストールし、`Add python.exe to PATH` とTcl/Tkを有効にします。ZIPを「すべて展開」し、書き込み可能なフォルダに置きます。ZIP内から直接batを実行しないでください。

1. **起動.bat** を開き、UTF-8の完成原稿TXTを選びます。`input/完成原稿.txt` に置く方法でも使えます。
2. **素材収集開始** を押します。目標候補枚数は初期100。進捗を画面で確認できます。
3. 自動で開くカタログから **採用・保留・不採用** を選び、最後に **採用画像を書き出す** を押します。

初回のみ「初回設定」で自分のWikimediaユーザーページURL（個人メール不要）を入力し、公式API条件・再利用条件を読んで確認欄を選択してください。URLと設定は `config/policy.json` に保存されます。以前のv0.3設定をコピーして使うこともできます。

毎回の権利条件URL・制作年代・クレジットの手入力は不要です。APIから取得できたものを表示し、欠けた情報は「不明」とします。要確認画像は出典へのリンクを表示し、画像自体は自動取得しません。要確認候補を「採用」にしても、権利条件を自動で許可へ変更せず、未取得として書き出し対象外になります。条件不明な資料の許諾を外部で確認して個別追加する機能は今後の拡張です。

API情報が明確な資料も、利用者は描写年代・制作年代・復刻かどうか等を出典で最終確認してください。カタログ内の「採用」は編集上の選択であり、法的な確認完了の宣言ではありません。

## 無料と有料AIの違い・設定

| モード | 費用と外部送信 | 解析内容 |
|---|---|---|
| 無料ルール（初期値） | AI料金なし。検索語とUser-AgentのみCommonsへ送信 | 文・話題転換による分割と、江戸のインフラ向け検索辞書。意味理解するAIではない |
| OpenAI API（任意） | 原稿全文をOpenAIへ送信。モデル・入出力トークン量によるAPI課金 | 原稿全体の文脈・人物・場所・時代・必要な画像・検索語・理由・重要度を構造化して解析 |

AIを使う場合：OpenAIのAPIアカウントでキーと利用枠を設定し、画面で有料AIを選び、「AI API設定」にキーと対応モデル名を入力します。初期モデル欄は `gpt-4.1-mini` ですが、利用可能なモデル・価格は公式ページで確認して変更できます。入力原稿30,000字まで、1回の解析で最大12,000出力トークン、自動再試行なし。入力トークン量やモデルにより料金が変わるため固定金額を表示しません。利用前に公式ダッシュボードで予算・利用量を確認してください。ChatGPT契約によるAPI枠の有無は利用者の契約によります。

- [公式API料金](https://developers.openai.com/api/docs/pricing)
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

「原稿送信とAPI課金を理解して利用する」を選んだ場合だけAIを呼びます。キーは画面内のみ・ファイル保存なし。空欄の場合は環境変数 `OPENAI_API_KEY` を使用できます。解析方式・モデル名・トークン使用量は結果の証跡へ記録します。APIキーはログ・カタログへ保存しません。AI呼び出しは `store:false`（これだけで提供元のすべてのデータ保持を無効にするものではありません）。

AIの返した原稿ブロックIDについて、原文の欠落・重複・順序変更を検査し、不正なら停止します。失敗したAI解析を、無料方式に黙って置き換えません。AI解析結果は「推定」、出典情報は「Commons APIメタデータ」と区別します。AIは史料の存在・権利・史実を確定するために使いません。

## 80〜120枚を目安にした収集

目標はGUIで変更でき、初期100枚です。原稿を通常200〜450字程度の意味のまとまりへ分割（無料方式は概ね260字を目安）し、シーンごとに3〜5枚を割り当てます。3枚ずつの基本枠を配り、残りは重要度の高いシーンへ優先配分します。全体目標を小さく指定した場合は3枚未満になることもあります。

各シーンの日英クエリを最大6個・各20件検索。実行全体は最大300クエリ。検索結果から具体語との一致がないもの、対象外ライセンス、同一pageid・SHA1・原本SHA256重複を除外します。おすすめ度は具体語・解像度・権利情報・年代注意点によるルール採点であり、画像の内容をAIが実見したスコアではありません。AIモードでは検索語自体がAI提案になります。

1画像は主たる1シーンに割り当て、同じ画像を別名で水増ししません。シーン別目標と実数、全体の不足はカタログと収集レポートに表示します。6シーンの短い原稿で100枚を満たすために無関係な画像を追加することはありません。画像を落とせた数と、候補として見つかった数は別です。

カウントの定義：

- **API発見**：APIが返した重複pageidを除く全件。関連性不足等を含みます。
- **関連候補**：シーン枠へ割り当てた、重複を除く画像候補数。
- **原本取得**：JPEG/PNG原本を実際に保存できた件数。サムネイルはこの数に加算しません。
- **条件分類可(API)**：PD/CC0/CC BYの必要情報がAPIで揃い、機械判定できた関連候補数。法的最終確認完了数ではありません。
- **要確認**：条件が不明・追加制限・許可対象外形式のライセンス等。画像未取得。
- **法的・史実的な最終確認完了**：自動機能では0件として扱います。

## カタログの保存と編集用書き出し

カタログはブラウザで開きます。アプリが起動している間は127.0.0.1のローカルサーバー経由で採否を結果フォルダへ保存します。外部へ公開しません。「過去のカタログを開く」で再編集できます。サーバーが要求を拒否した場合や条件不明な画像は未取得として記録します。

`素材カタログ.html` を直接開いた場合も、検索・拡大・選択操作ができます。ただし採否はブラウザのローカル保存になり、直接ファイルを書き換えられません。「選択をJSON保存」し、アプリの「選択JSON読込・書き出し」で該当結果フォルダに反映できます。ブラウザの保存設定によりローカル保存できない場合はJSON保存を使ってください。

```text
results/大和噺_原稿名_日時/
  素材カタログ.html
  素材一覧.csv
  取得済み.csv / 利用条件未確認.csv / 取得見送り.csv / 取得エラー.csv
  クレジット一覧.txt
  収集レポート.md / 実行結果.json / catalog.json
  使用原稿.txt
  候補原本/             # 自動分類できた候補を原本無改変保存
  サムネイル/
  証跡/                 # API応答・robots・検索・AI解析
  除外候補.json
  編集用/書き出し日時/
    001_導入など/
      S001_資料名_WC資料ID.jpg
    002_江戸の都市規模など/
    クレジット一覧.txt
    書き出し結果.json
```

シーン名・数は実原稿によって変わります。書き出すたびに新しいフォルダを作り、以前の採用版を消しません。採用した原本だけをコピーします。CSV・クレジット案も出典APIに基づくため、動画でのトリミング・合成等を行う場合は変更表示など必要条件を確認してください。Resolveへは編集用の各シーンフォルダをメディアプールへ読み込みます。タイムライン自動生成は未実装です。


## Windowsで原本10枚を再検証する

1. v0.5 ZIPを**新しいフォルダ**へ展開します。旧版は残してください。
2. 旧版の `config/policy.json` をコピーするか、初回設定でWikimediaユーザーページURLを登録します。個人メール不要です。
3. **Commons取得テスト.bat** をダブルクリックし、**江戸・10枚取得テスト** を押します。
4. 結果の `10枚取得テスト結果.json` で `verified_original_files` と `goal_met` を確認します。目標は原本10枚。候補25枚・サムネイル10枚だけで成功にはしません。
5. カタログでクリック拡大し、`候補原本` に画像が10枚あることを確認します。実物の資料内容・権利の最終確認は別です。

不足時は `network` / `errors` / `v03通信方式比較.json` / `証跡/通信ログ.jsonl` を確認してください。通信ログは `action-api` と `media`、HTTP状態、エラー、応答時間、再試行を分けます。403でUAを変える、プロキシを外す、別ホストへ切り替える等の処理はしません。

v0.3と同じAPIパラメータで候補最大10件の比較検索も記録します。ユーザーが報告したv0.3の候補10件と、今回の比較検索・原画像保存10枚は別の指標です。拒否・待機指示・中止がある場合は比較の追加通信もしません。

## 開発者向けの実画像テスト

**Commons取得テスト.bat** を開き、「江戸・10枚取得テスト」を押します。テストは無料ルール解析、候補最大25枚から原本10枚の保存を目標に、同梱の江戸10枚取得テスト原稿で、実際のAPIへアクセスします。架空の画像やAPI応答へ自動で差し替えません。

確認項目：

1. 画面の発見数・関連候補数・原本取得数・条件分類数を確認。
2. カタログに実際のサムネイルが表示され、クリックで原画像が開くか確認。
3. 出典ページを開き、資料名・条件を照合。
4. 画像を採用して書き出し、編集用フォルダに実ファイルがあるか確認。
5. 不足・エラーは収集レポートで確認。取得0件は成功ではありません。

開発者向けには、ブラウザ自動検証用の任意パッケージを `python -m pip install playwright` で追加し、`python live_smoke.py --run --browser` で、本物の検索・原画像保存・Chrome/Edgeによる画像デコードまで検証します。原本10枚を保存・SHA256照合でき、ブラウザでも10画像がデコードされた場合だけ全体成功になります。通常のGUI利用にPlaywrightは不要です。利用条件確認後のみ実行してください。実画像0件やデコード失敗は終了コード非0になります。CI用User-Agentは、この公開GitHubプロジェクトURLを連絡先とする形式です。個人の架空の利用者名を送信しません。

GitHub ActionsにはWindowsでの単体テストと実画像のsmokeテストを設定します。接続先・一時障害により実画像テストが失敗した場合もログと成果物をアップロードします。実画像テストの結果は単体テストと別に確認してください。

## 接続条件・アクセス制御

必要ホスト：`commons.wikimedia.org`、`upload.wikimedia.org`、`thumb.wikimedia.org`。公式条件確認に `www.mediawiki.org`、`foundation.wikimedia.org`、`creativecommons.org` 等。有料AIを選んだ場合だけ `api.openai.com` が必要です。

公開APIのみを使い、資料HTMLをスクレイピングしません。原本はAPIが返した画像URLだけを許可します。HTTPS・TLS検証・通常のプロキシ設定を維持し、ログイン・アクセス制限を回避しません。API呼び出しは固定エンドポイントと許可した読み取りパラメータだけを受け付けます。画像URLにはrobots.txtを取得して禁止対象を拒否し、取得不能なら画像を自動取得しません。Crawl-delay/Request-rateを反映し、通常は逐次1.1秒以上間隔、maxlag=5。1秒超のAPI応答後は次の要求まで5秒待ちます。API/robotsにgzipを要求し、メディアは2,000,000 bytes/秒以下に制限します。429/503/maxlagは限定回数の待機再試行、長いRetry-Afterは停止して再実行を案内します。401/403は回避せず停止。ネットワーク失敗時も空のカタログとレポートを作ります（原稿解析自体が失敗した場合はログに記録して終了）。

画像は原本1枚80MBまで、JPEG/PNGのみ。TIFF/PDF/IIIF合成・近似重複・AI視覚分析・国内機関自動取得は未実装。100枚で数百MB以上になることがあるため空き容量が必要です。中止は現在の通信が戻った後に反映され、取得済み結果を残します。
